# Manual Test Run — 2026-06-01

Driver: agent-assisted, executed live against `http://localhost:3000` (Next dev) via the Claude Preview browser + API calls in the page context. Followed the doc's **suggested run order**. User drove the Razorpay modals.

## Environment constraints discovered (affect how cases can be run)

1. **Live Razorpay completion cannot run inside the Claude Preview sandbox.** The preview only permits `localhost` navigations; Razorpay's test flow (card 3DS/OTP page, netbanking bank page, UPI success callback) redirects to external `razorpay.com` URLs, which the sandbox blocks ("Link to was blocked. Preview only supports localhost URLs."). The modal opens (iframe) but can never *complete*. → All live-charge cases must be run in a real Chrome at `localhost:3000`.
2. **Razorpay is in TEST mode** (`rzp_test_…`) — no real money is ever charged. Min order = ₹1 (₹0.50 would be rejected).
3. **File uploads (xlsx/CSV) are not reliably drivable** via the preview tools → bulk-import cases (TC-OWN-05/07, TC-CCQ-01, template flows) deferred to manual.
4. **Connection pool is small (limit 17, 10s timeout).** A burst of rapid concurrent API calls triggered a transient `PrismaClientKnownRequestError P2024` on `/coaching/tests/new` (`listClasses`). Cleared on reload. Could recur under real concurrent load — worth watching.

## Bugs & findings

1. **🐛 Bundle checkout 403 for students (FIXED during run).** Checkout fetched bundle details from admin-only `/api/admin/bundles/[id]` → 403 → "Item not found"; no student could buy a bundle. Fix landed: public `/api/bundles/[id]` + checkout points at it ([checkout/page.tsx:76](../../src/app/checkout/page.tsx)). Verified loads.
2. **🐛 Razorpay webhook returns 500, not 401, on bad signature (TC-WH-01 FAIL).** `verifyWebhookSignature` ([razorpay.ts:16](../../src/lib/razorpay.ts)) throws instead of returning false: (a) `createHmac` with empty `RAZORPAY_WEBHOOK_SECRET!`, (b) `crypto.timingSafeEqual` throws on buffer length mismatch (short/garbage signature). Fix spawned. Still rejects the request (no security hole) but wrong status.
3. **ℹ️ `board` silently dropped** on student signup/profile — `/api/auth/me` returns `board:null`; documented as a known limitation in `student/profile/route.ts` (no legacy column). Confirmed, not new.
4. **ℹ️ `/dashboard` (B2C) doesn't server-redirect logged-out users** — returns 200 + blank body (vs `/coaching` & `/admin` which redirect). No data leak, but inconsistent gating.
5. **ℹ️ Error envelope inconsistency** — 503 (import) and 422 (invalid test id) return `{ok:true, data:{error}}` rather than the `{ok:false, error}` convention. HTTP status correct.
6. **ℹ️ Connection pool P2024** under burst load (limit 17 / 10s). Transient here; monitor under concurrency.
