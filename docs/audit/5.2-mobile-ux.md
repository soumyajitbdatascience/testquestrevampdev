# Phase 5.2 — Mobile UX final pass

Date: 2026-05-29
Auditor: Claude agent (Task 5.2)
Viewport tested: 360×640 (budget Android baseline)
Method: source-code audit of all 24 target pages plus shared layout components
(CoachingHeader, AdminSidebar, WizardShell). No browser driving — every
finding below is reasoned from explicit Tailwind classes in the JSX.

## Executive summary

The shell-level nav primitives are the biggest mobile gap: the **coaching
header hides every nav link below `sm` (640px) without any hamburger menu**,
and the **admin sidebar never collapses to a drawer** — both make whole
sections of the app unreachable on a phone. Otherwise content templates are
mostly mobile-aware (responsive grids, `flex-wrap`, `sm:` breakpoints), but
several high-traffic surfaces have specific failures: the test-taking page
hides the question palette behind `lg:`, the admin questions/tests pages put
multi-column tables in `overflow-hidden`, and many critical tap targets
(checkbox icons in bulk-assign, batch-rename pencil, sort arrows in builder
tray) are well under 44 px.

Top 3 by severity:
1. **F1** — Coaching header has no mobile menu (Tests/Settings/Team/Branches/Help unreachable <640px)
2. **F2** — Admin sidebar never collapses — every admin page broken on phones
3. **F3** — Test-taking page hides question palette (jump grid + legend) on `<lg` so students can't navigate questions

## Findings (priority order)

### F1 — Coaching header drops every nav link on mobile with no hamburger
**Severity**: HIGH
**Page**: `/coaching/*` (file: `src/app/coaching/**/page.tsx` via `src/components/coaching/coaching-header.tsx` lines 90–138)
**Symptom**: All seven nav targets (`Tests`, `Questions`, `Team`, `Settings`, `Branches`, `Help`, role badge) are marked `hidden sm:inline` / `hidden sm:inline-flex`. Below 640 px the header collapses to just `Logo + ThemeToggle + Sign out`. There is no drawer, no dropdown, no overflow menu.
**Impact**: On a phone an owner who lands on `/coaching/dashboard` cannot reach `/coaching/tests`, `/coaching/questions`, `/coaching/team`, `/coaching/settings/branding`, `/coaching/branches`, or `/help` without typing the URL. Equivalent to losing the global nav.
**Recommended fix**: Add a `<MobileNavSheet>` (shadcn `Sheet` + hamburger) shown `sm:hidden`. Same link list, full-width tap rows, 48 px min height. Hide the existing `sm:inline` Links unchanged.
**Estimated effort**: M

### F2 — Admin sidebar never collapses to a mobile drawer
**Severity**: HIGH
**Page**: every `/admin/(authenticated)/*` route (file: `src/app/admin/(authenticated)/layout.tsx`, `src/components/admin/admin-sidebar.tsx` line 83+)
**Symptom**: The layout is `flex`, sidebar is permanently `sticky w-64` (or `w-16` collapsed). No `md:` / `lg:` breakpoint, no `Sheet`. At 360 px the sidebar consumes 64 px (collapsed) or 256 px (expanded) of width — main column becomes 96–296 px and tables inside immediately overflow.
**Impact**: Entire admin section unusable on a phone. Tables truncate, controls overlap.
**Recommended fix**: Wrap `AdminSidebar` in a Sheet that becomes the off-canvas drawer below `lg`; render an `AppBar` with hamburger on mobile inside the layout. Existing desktop behaviour stays via `hidden lg:flex` on the sidebar.
**Estimated effort**: M

### F3 — Attempt page hides question palette + flag legend on `<lg`
**Severity**: HIGH
**Page**: `/attempts/[id]` (file: `src/app/attempts/[id]/page.tsx` line 209, 320)
**Symptom**: Layout is `grid gap-6 lg:grid-cols-[1fr_280px]`. The `<aside>` containing the 5×N question palette, answered/flagged legend, and the "Practice mode" callout is in the second column — at `<lg` (1024 px) it stacks **below** the question, but the only way to reach it is to scroll past the entire question + Prev/Next row, with no anchor or sticky shortcut. Students cannot jump between Q3 → Q17 without tapping Next 14 times.
**Impact**: Real exam UX broken on phones — this is the single most critical student flow.
**Recommended fix**: At `<lg`, render the palette as a collapsible bottom-sheet triggered by a sticky "Questions (3/30)" pill in the header (between timer and Submit). Reuse the existing aside markup inside the sheet.
**Estimated effort**: M

### F4 — Admin questions/tests tables overflow at 360 px (wrapper has `overflow-hidden`)
**Severity**: HIGH
**Page**: `/admin/questions`, `/admin/tests`, `/admin/bundles`, `/admin/coupons`, `/admin/orders` (file: `src/app/admin/(authenticated)/questions/page.tsx` line 302, similar in others)
**Symptom**: Tables have 6 columns (Question/Type/Difficulty/Chapter/Used in/Actions) wrapped in `rounded-2xl border ... overflow-hidden`. No horizontal scroll. Content will either spill (cropped) or compress columns illegibly.
**Impact**: Admin can't see most table columns on mobile.
**Recommended fix**: Swap `overflow-hidden` → `overflow-x-auto`, set `<Table className="min-w-[720px]">`. Or add a `lg:hidden` card-list view that renders the same rows as stacked cards.
**Estimated effort**: S (overflow swap) / M (card view)

### F5 — Assign-test "Also assign to" checkboxes are 14 px tap targets
**Severity**: MEDIUM
**Page**: `/coaching/batches/[id]/assign` (file: `assign-client.tsx` lines 238, 257)
**Symptom**: `<input type="checkbox" className="h-3 w-3" />` (12 px) for the "this batch" pill and `h-3.5 w-3.5` (14 px) for each extra-batch row. Rows are `px-3 py-2` so the row itself is ~36 px, still <44.
**Impact**: Bulk-assign is a flagship feature. Mis-taps on 14 px checkboxes cause wrong batches to receive a test — high-stakes failure.
**Recommended fix**: Bump to `h-4 w-4` minimum; pad each row to `py-3` (≥44 px); make the entire label clickable (it already is — just enlarge hit area). Use `accent-primary` (already present) for native check styling.
**Estimated effort**: S

### F6 — Builder tray reorder/remove buttons are 12–16 px arrows
**Severity**: MEDIUM
**Page**: `/coaching/tests/new` (file: `builder-client.tsx` lines 593–599)
**Symptom**: Up/down/remove buttons are bare `<button>` with `p-1` and a single emoji/glyph (`↑` `↓` `<X className="h-3 w-3" />`). Approx 20 px total hit area, grouped tightly (`gap-0.5`).
**Impact**: Reordering picked questions is fiddly on a phone — taps will hit the wrong row.
**Recommended fix**: `p-2`, `min-h-[36px] min-w-[36px]`, increase spacing to `gap-1`. Consider replacing reorder with a long-press-drag DnD on mobile.
**Estimated effort**: S

### F7 — Batch rename pencil + check/cancel icons are 28 px
**Severity**: MEDIUM
**Page**: `/coaching/batches/[id]` (file: `batch-client.tsx` lines 244–273)
**Symptom**: Pencil/Check/X edit icons use `p-1.5` or `p-2` around `h-3.5 w-3.5`/`h-4 w-4` glyphs — ~28–32 px total. Below AHIG 44 px and tightly adjacent.
**Impact**: Owners often rename batches on the go; tiny icons.
**Recommended fix**: `p-2.5` and `h-4 w-4` glyphs; or wrap in `Button size="icon"` shadcn variant which already enforces 36 px.
**Estimated effort**: S

### F8 — Attempt header "Pause/Submit" + timer crowds at 360 px
**Severity**: MEDIUM
**Page**: `/attempts/[id]` (file: `src/app/attempts/[id]/page.tsx` lines 178–202)
**Symptom**: Header contains LogoMark, optional timer pill (`px-4 py-1.5 font-mono`), Pause button, Submit button inside `h-14 container`. At 360 px the timer "1:23:45" + "Submit" alone are ~200 px; adding Pause forces wrap or truncation. The test name is `hidden sm:inline` (OK) but Pause label is also `hidden sm:inline` so the Pause icon is bare 32 px.
**Impact**: Submit button can be clipped or pushed below; Pause is unlabeled icon.
**Recommended fix**: Drop the timer to `px-3 text-xs` below `sm`; combine Pause+Submit into a single overflow menu (`MoreVertical`) on mobile or anchor Submit only.
**Estimated effort**: S

### F9 — Tabs on Batch detail use `overflow-x-auto` but no scroll affordance
**Severity**: LOW
**Page**: `/coaching/batches/[id]` (file: `batch-client.tsx` line 313)
**Symptom**: `<TabsList className="overflow-x-auto justify-start max-w-full">`. Works (three tabs fit at 360 px), but the disabled "Reports" tab still renders with no indication it's off-screen on narrower locales. Also no fade-edge or scroll-snap, so iOS rubber-banding feels janky.
**Impact**: Minor — tabs are reachable. Same pattern in monitor-client.tsx line 222.
**Recommended fix**: Add `scroll-snap-type-x snap-mandatory` and a `pl-1 pr-1` to TabsList; add fade gradient.
**Estimated effort**: S

### F10 — `<select>` elements used throughout (transfer dialog, builder filters)
**Severity**: LOW
**Page**: `/coaching/batches/[id]` transfer dialog, `/coaching/tests/new` filters (files: `batch-client.tsx:407`, `builder-client.tsx:276/337/350/557`)
**Symptom**: Native `<select>` elements. iOS Safari renders them as a wheel picker that's actually fine, but Android Chrome renders a tiny grey dropdown that can be missed; the styling diverges from shadcn `Select` used elsewhere (visual inconsistency).
**Impact**: Visual inconsistency + worse styling on Android.
**Recommended fix**: Replace with shadcn `Select` (already imported in admin pages). Same behaviour, consistent UI.
**Estimated effort**: M (multiple files)

### F11 — Datetime-local input on `/coaching/batches/[id]/assign`
**Severity**: LOW
**Page**: assign-client.tsx line 279
**Symptom**: `<Input type="datetime-local" />` — height `h-11` is fine, but on mobile this triggers OS picker which on iOS <16 is a wheel that may not match brand. Also there is no min/now constraint, so users can pick a past due date.
**Impact**: Minor UX nit + data quality (past due).
**Recommended fix**: Add `min={new Date().toISOString().slice(0,16)}`. Optionally split into date + time inputs for better mobile keyboards.
**Estimated effort**: S

### F12 — Wizard footer (sticky Next/Back) — no audit of overlap with keyboard
**Severity**: MEDIUM
**Page**: `/coaching/setup` (file: `src/components/coaching/wizard-shell.tsx`)
**Symptom**: Shell shows a sticky footer with Next/Back. When a step focuses an `<input>` (e.g. step-batch's "Batch name"), iOS Safari raises the keyboard which overlaps the sticky footer. User can't see the "Save & continue" CTA without dismissing the keyboard.
**Impact**: Setup is the first thing every owner sees — confusion here costs activation.
**Recommended fix**: Use `pb-[env(safe-area-inset-bottom)]` and add a `keyboard-aware` adjustment (e.g. shrink footer to `position: relative` when an input is focused via `useVirtualKeyboard` or listen to `visualViewport.resize`).
**Estimated effort**: M

### F13 — Coaching dashboard "New batch" button uses 11.5 px font on mobile
**Severity**: LOW
**Page**: `/coaching/dashboard` (file: `src/app/coaching/dashboard/page.tsx` line 141)
**Symptom**: `px-4 py-2.5 text-sm` is fine (44 px height), but the button + greeting stacks; on a phone the New batch CTA is below the H1 which itself is `text-4xl md:text-5xl` (36 px) — pushes the CTA below the fold on a 640 px viewport.
**Impact**: Primary CTA below the fold on cold start.
**Recommended fix**: On mobile, render New batch as a floating action button or above the H1.
**Estimated effort**: S

### F14 — Coaching login mode toggle pill at `text-xs px-3 py-1.5` (~28 px tall)
**Severity**: LOW
**Page**: `/coaching/login` (file: `src/app/coaching/login/page.tsx` lines 34–50)
**Symptom**: The Email/Mobile-OTP toggle is a 2-button segmented control at 28–30 px height. Sub-44 px, tightly packed.
**Impact**: Mis-taps switching modes during sign-in.
**Recommended fix**: Bump to `py-2.5 text-sm` (≥40 px); add `min-h-[44px]`.
**Estimated effort**: S

### F15 — Public landing has nav `hidden md:flex` with no mobile menu

**Page**: `/` (file: `src/app/page.tsx` lines 86–104)
**Symptom**: Section anchors (How it works / Subjects / Pricing / FAQ / For centres) hidden below 768 px. No hamburger; only the Start-free CTA shows. "Sign in" link `hidden sm:inline-flex`.
**Impact**: Marketing landing on a phone has no in-page nav; users must scroll the entire page or know to deep-link.
**Recommended fix**: Add a hamburger triggering a `Sheet` with the same 5 links and Sign-in CTA.
**Estimated effort**: S

### F16 — Attempt option cards (SINGLE_MCQ) — entire button is tap-friendly, but text contrast at 14 px option labels
**Severity**: LOW
**Page**: `/attempts/[id]` lines 246–253
**Symptom**: The option-letter chip is `h-8 w-8` (32 px) — borderline. Below 44 px AHIG but the whole 64 px row is a tap target, so functionally fine.
**Impact**: Pass — flagged only as a borderline target.
**Recommended fix**: None required. If polishing, `h-9 w-9`.
**Estimated effort**: —

### F17 — Long unbreakable strings: org name, batch name, student email
**Severity**: LOW
**Page**: `/coaching/dashboard`, `/coaching/batches/[id]`, `CoachingHeader`
**Symptom**: `truncate max-w-[220px]` on header org name (good). Batch header `h1 truncate min-w-0` (good). But `BatchListItem` / `StudentListItem` not audited — long emails like "rohit.kumar.sharma@gmail.com" may break narrow cards.

## Things that pass cleanly

- `/coaching/signup` form fields — `h-11` (44 px) inputs, proper `Label htmlFor`, `inputMode="numeric"` on Expected students and mobile.
- `/coaching/login` OTP code input — `inputMode="numeric"`, `autoComplete="one-time-code"`, `h-11`.
- Wizard progress bar has a clean mobile variant (`md:hidden` vs `hidden md:flex` dot list at `wizard-shell.tsx` lines 70–84).
- Coaching dashboard stat grid is responsive (`grid-cols-2 lg:grid-cols-4`).
- Attempt page header uses `overflow-x-hidden` on the parent and `truncate` on test name — won't horizontally scroll.
- Transfer dialog (Task 4.5) uses shadcn `Dialog` with `max-w-md` — scales fine.
- Test detail card stats (`grid-cols-3 gap-px`) reads OK at 360 px.

## Out of scope (Phase 6)

- Visual polish (font sizes, line heights, dark-mode contrast deltas).
- iOS Safari `100vh` issues (no `100vh` found in audited pages — appears already addressed).
- Image performance (no `<Image>` audit done).
- Accessibility audit (separate Phase 6 a11y pass needed; flagged a few `aria-label` absences in icon-only buttons but not exhaustive).
- Pages not directly opened by an audited file: `/coaching/assignments/[id]` student-facing intro (only the file path was confirmed), `/coaching/team/accept/[token]`, `/coaching/welcome/[token]`, `/admin/organizations/[id]` parent-picker (only file size checked), `/help`, `/for-coaching-centres` (only landing patterns sampled). Parent agent should spot-check these on device.

## Risks / caveats

- All findings are static-source reasoning. Two findings (F12 keyboard overlap, F4 admin table behaviour) need real-device confirmation — F12 may already be addressed if `WizardShell` uses non-sticky footers (I read the first ~100 lines only).
- F3 (attempt palette) may be intentionally deferred — if the product wants students forced to step sequentially on mobile, this is a feature, not a bug. Verify with PM.
- Tap-target measurements assume default Tailwind `1rem = 16 px` and no global font scaling.
